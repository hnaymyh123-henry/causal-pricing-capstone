# Causal and Predictive Models for Retail Pricing Decisions

Code and results for the NUS capstone report *Causal and Predictive Models for
Retail Pricing Decisions* (2026).

When a retailer sets prices from observational sales data, should it estimate the
causal effect of price or fit a predictive demand model? This project compares both
in a simulation where the true answer is known. Weekly product-level panels are
generated with scales calibrated to the M5 (Walmart) data. Four price-effect
estimators — instrumental variables (IV), double machine learning (DML),
DirectLiNGAM and naive OLS — and three predictive models — histogram gradient
boosting (HGB) and two tabular Transformers trained from scratch — each choose one
of seven candidate prices (−15% to +15% of the current price) for every
product-week. Each choice is scored with simulator-known demand as **Oracle
regret**: the share of the best achievable profit that is lost. Five worlds vary the
price sensitivity and the identifying conditions (instrument strength, hidden
confounding, instrument validity).

## Main result

Mean Oracle regret (%) on matched seeds 0–4, five seeds per cell (report Table 6 and
Figure 2). The predictive models use training-relative log price.

| Method | Inelastic | Clean elastic | Weak instrument | Hidden confounding | Invalid instrument |
|---|---:|---:|---:|---:|---:|
| IV | 0.00 | 0.00 | 1.46 | 0.00 | 7.14 |
| DML | 0.00 | 0.00 | 0.00 | 6.07 | 0.00 |
| Naive OLS | 0.00 | 3.26 | 4.28 | 6.66 | 4.86 |
| DirectLiNGAM | 0.00 | 0.00 | 0.00 | 6.07 | 0.00 |
| HGB | 0.42 | 1.76 | 1.86 | 7.32 | 1.95 |
| Tabular Small | 0.00 | 0.64 | 0.70 | 6.35 | 0.66 |
| Tabular Large | 0.00 | 0.51 | 0.49 | 6.38 | 0.51 |

Across the four elastic worlds, the causal group (IV, DML, DirectLiNGAM) loses 1.73%
of the achievable profit on average and the predictive group (HGB, Small, Large)
2.43%. The gap is 0.70 percentage points (95% Monte Carlo interval 0.45–0.94 over
five seed blocks), and the causal group is lower in 14 of 20 world-seed cells. Each
causal estimator loses profit only where its identifying assumption breaks (IV with
a weak or invalid instrument, DML and DirectLiNGAM under hidden confounding); under
hidden confounding only IV, whose instrument stays valid, avoids the loss.

## Setup

The reported results were produced on CPU with Python 3.11 and the package versions
pinned in `requirements.txt` (report Appendix B, Table B2).

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
# CPU build of PyTorch 2.7.1 (Windows/Linux; on macOS: pip install torch==2.7.1)
pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
```

`code/experiment.py` trains the Transformers on a CUDA GPU automatically when one is
visible. GPU arithmetic differs slightly from CPU arithmetic, so to reproduce the
reported Transformer numbers exactly, use the CPU build above or hide the GPU
(`CUDA_VISIBLE_DEVICES=""`).

## Data

The experiments do **not** read external data: every panel is generated by the
simulator in `code/experiment.py` from fixed parameters and seeds. The raw M5 files
were used only to calibrate those parameters (report Sections 3.2–3.3) and are not
redistributed here, because they are Kaggle competition data. To rerun the
calibration checks, download them as described in
[data/m5/README.md](data/m5/README.md).

## Reproducing the results

Run every command from the repository root. Times are wall-clock times measured on
a 4-core laptop CPU (Intel Core i7-1165G7); the full reruns in steps 3 and 4 are
extrapolated from their measured one-world, one-seed runs.

**1. Quick demo (about 3.5 minutes).** Two worlds, one seed and a small panel (80 products ×
80 weeks) for all seven methods. Note that `--output` of `experiment.py` is relative
to the `code/` folder.

```bash
python code/experiment.py --quick --output ../results/quick_demo
```

**2. Re-score the saved main comparison (about 30 seconds).** Regenerates the test data of all
25 world-seed combinations and re-scores the 175 saved price decisions (and the 75
saved forecast matrices) against simulator-known demand. It also checks that
`code/experiment.py` has the SHA-256 recorded for the run. No model is trained.

```bash
python code/relative_price/verify_results.py
```

**3. Rerun the main comparison (about 2 hours, estimated; report Tables 6 and 8, Figures 2 and 3).**

```bash
python code/relative_price/run_experiment.py
python code/relative_price/verify_results.py  --results-dir results/relative_price_reproduced
python code/relative_price/analyze_results.py --results-dir results/relative_price_reproduced
python code/relative_price/plot_figures.py    --results-dir results/relative_price_reproduced
python code/compare_results.py results/relative_price/seed_results.csv results/relative_price_reproduced/seed_results.csv
```

`run_experiment.py` refits all seven methods in five worlds × five seeds and writes
to `results/relative_price_reproduced/`; while it runs, it asserts that the four
slope estimators reproduce the archived estimates and regrets. For a shorter check
(about 4.5 minutes), run one world and seed with
`--worlds higher_elasticity --seeds 0` and skip `analyze_results.py`, which needs
the complete run.

**4. Rerun the 30-seed benchmark (roughly 2–2.5 hours, estimated; report Tables 7 and 10).** The first command
runs IV, DML, naive OLS, DirectLiNGAM and HGB for seeds 0–29; the second adds both
Transformers (original absolute-price input) for seeds 0–4.

```bash
python code/experiment.py --methods IV,DML,Naive,DirectLiNGAM,HGB --output ../results/benchmark_reproduced
python code/experiment.py --methods TransformerSmall,TransformerLarge --seeds 0,1,2,3,4 --resume --output ../results/benchmark_reproduced
python code/compare_results.py results/benchmark/seed_results.csv results/benchmark_reproduced/seed_results.csv
```

A one-world, one-seed check takes about 4 minutes:
`python code/experiment.py --worlds higher_elasticity --seeds 0 --output ../results/benchmark_reproduced`.

**5. Fixed price policies (a few seconds; report Table 9).**

```bash
python code/diagnose_fixed_policies.py
```

**6. M5 calibration checks (about 30 seconds; needs the M5 files; report Sections 3.2–3.3).**
Prints the CA_3/FOODS panel size (1,437 products, 277 weeks, 322,166 product-weeks)
and the price and demand scales used to set the simulator parameters.

```bash
python code/calibrate_effect_sizes.py
```

## Reproducibility notes

- **Determinism.** Every random draw is seeded: the simulator by the world seed, HGB
  by `random_state=seed`, and the Transformers by `torch.manual_seed(seed)`, fixed
  per-epoch shuffling seeds and four CPU threads. In the pinned environment, reruns
  reproduce the saved results bit for bit (see the verification above). Other CPUs
  or library versions can change floating-point rounding, which may move individual
  Transformer or HGB price choices; the slope estimators are checked against the
  archived values during every rerun.
- **Provenance.** `code/experiment.py` is byte-identical to the file used for every
  reported run: SHA-256
  `018f259ad573c165f19de549dde6b2b987df4f6a0f1928b53f95dddad7b4d550`, as listed in
  report Appendix B, Table B2. `.gitattributes` turns off line-ending conversion so
  the hash also holds after cloning on macOS or Linux.
- **Changes for publication.** The experiment logic is unchanged. For portability:
  `relative_price/run_experiment.py` takes the output folder, worlds and seeds as
  options (by default it writes to a new folder, as report Appendix B advises) and no
  longer hashes local report documents; `relative_price/verify_results.py` no longer
  needs a local path-mapping file; `relative_price/analyze_results.py` no longer
  writes a Chinese copy of `RESULTS.md`. `relative_price/plot_figures.py` (the
  original plotting script for Figures 2–3 was not kept) and `compare_results.py` are
  new, and `diagnose_price_anchor.py` records repository-relative paths. In
  `results/`, absolute local paths in `relative_price/manifest.json` were replaced
  with project-relative paths, and four derived files were regenerated in the pinned
  environment (see [results/README.md](results/README.md)); no reported number
  changed.
